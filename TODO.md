## Accuracy, to check later

- [ ] Fast timing: sprites are a frame ahead of the background scroll compared with the board (at most ~1 pixel against the ground); arcade timing is exact
- [ ] Arcade timing: MAME draws 90 us into the vblank interrupt; we draw when it returns. Same except perhaps during a large palette fade (one frame)
- [ ] Sound: our resampling to 48 kHz is simpler than MAME's (straight lines between samples); compare against MAME recordings
- [ ] Sound: OKI commands take effect at the end of the frame (up to ~17 ms late; the reference runs agree)

## Future ideas

- [ ] **Online multiplayer** (owner; the LOWEST priority of everything here: last, if at all): two players over the internet. The game is deterministic (the same inputs give the same frames, as the reference checks show), so it suits rollback netplay (as GGPO): each side runs the game, sends its inputs, predicts the other's and rolls back with save states when a guess was wrong. Needs: save states that are quick enough to make and load several times a frame (now the whole board and the game task's stack), a connection between players (direct, or a free relay/matchmaking server for NAT), a lobby in the menu, and both sides checked to run the same version and ROM data. A big job: after the other features
